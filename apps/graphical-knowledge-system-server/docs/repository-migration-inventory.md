# GEODE repository migration inventory

Status: working integration record, 2026-08-27.

GEODE is the editable local-first Markdown application. It should converge compatible application work already present in this repository without turning every specialized product into mandatory GEODE semantics.

## High-value predecessors

| Existing system | Proven capabilities | Direction into GEODE | Boundary to preserve |
| --- | --- | --- | --- |
| L-Space | Collections, breadcrumbs, room cards, tags, typed doors, search, keyboard routing, deterministic atlas, sharded on-demand room loading | Migrate generic navigation and reading patterns through TUFTE; consume its shared compiler projections | Retain science identity, Cloudflare/D1 deployment, authentication, and VaultMaze learning policy in the situated application |
| Bare Cedar Fog Markdown vault services | Repository-wide Markdown census, explicit physical-vault policy, current/legacy/reference provenance, bounded ripgrep search with line evidence, semantic-lightcone retrieval | Add a policy adapter for this repository and extract any generally reusable search/change-batch contracts | Do not make Bare Cedar Fog's repository taxonomy the generic GEODE kernel |
| Vault compiler | Deterministic House Markdown, Obsidian, and bounded Org adapters; wikilinks, aliases, tags, cards, FCA halls, layouts, canonical World validation | Offer an optional semantic-vault projection in GEODE | Ordinary Markdown must remain openable and editable without becoming rooms, doors, halls, or cards |
| VaultMaze | Separate SPACE meaning from TUFTE arrangement; multi-wing configuration and optional passage evaluation | Integrate as an optional GEODE workspace mode | Authentication, access, review gates, and learning credit remain product/deployment policy |
| Legacy digital garden | Historical graph/search/feed/template and visual-design precedent | Treat as UX and compatibility research | Do not revive its archived Eleventy dependency stack |
| VICTOR | Reproducible catalogs, releases, feeds, archives, PWA and publication projections | Publish admitted GEODE snapshots downstream | VICTOR does not become the editable workspace runtime |

## Migration order by direct user value

1. **Repository-scale opening and retrieval.** Stop relying on a single eager 100,000-file scan. Add explicit workspace policies, on-demand carrier reading, provenance-aware repository search, default tool/build exclusions, progress, and incremental refresh.
2. **Navigation that supports daily use.** Bring collections/folders, breadcrumbs, recent and pinned notes, tabs/history, room-card density, tags, and typed-neighborhood panels into TUFTE and GEODE.
3. **Trustworthy editing.** Add proposal/diff, witnessed commit, structured edits, undo/recovery, filesystem watching, and external-edit reconciliation around the existing revision-guarded write.
4. **Optional semantic modes.** Project a workspace through vault-compiler and SPACE without making that World the authoritative Markdown carrier.
5. **World-class retrieval.** Extract a shared incremental document-search contract; combine title/path/metadata ranking, exact line evidence, typed graph traversal, and explainable semantic-lightcone projection.
6. **Collaboration.** Implement the authoritative sequenced alpha law, presence, attributed operations, causal undo, replay, and Markdown checkpoints.
7. **Ecosystem and publication.** Add a capability-scoped extension host, Canvas/structured-data surfaces, import/export compatibility, mobile/PWA quality, and VICTOR publication.

## Consolidation work

- Lenticule's browser currently reconstructs TUFTE tiles manually. Generic tile, collection, breadcrumb, atlas, and search-result forms should move into TUFTE or a reusable knowledge-browser adapter before GEODE consumes them.
- GEODE and Lenticule each have private metadata search. Their useful laws should become one upstream document-search projection rather than a third implementation.
- Vault compiler vendors compiler/FCA/card/layout modules from Lantern. Neutral modules should settle beneath both consumers after parity tests identify the real shared law.
- Bare Cedar Fog policy remains a selectable repository adapter. Generic filesystem change batches and search receipts may be extracted beneath it and GEODE.
- The active engineering QwzSpace and public copy should converge before GEODE collaboration begins borrowing resume/history behavior.

## Competitive discipline

The current capability benchmark treats Obsidian, Roam, Notion, Logseq, and Etherpad as independently moving targets. GEODE must meet table stakes across the whole class—fast capture, navigation, retrieval, backlinks, properties, history, collaboration, extension, import/export, offline behavior, and mobile usability—while preserving its differentiators: authoritative ordinary files, explicit typed relations, inspectable receipts, sovereign hosting, and honest convergence laws.

Each implementation slice must answer three questions:

1. Which real user workflow becomes materially better?
2. Which predecessor or upstream package already proves part of it?
3. Which adjacent product dimension are we neglecting by focusing here?
