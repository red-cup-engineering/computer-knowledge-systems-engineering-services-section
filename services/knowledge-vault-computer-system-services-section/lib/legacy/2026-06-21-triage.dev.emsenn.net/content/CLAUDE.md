# How to organize files in 561-group/content/

This is an Indigenous Lakota knowledge project. Its files are organized by the
relational, generative method this corpus proves about itself — Curry–Howard
directionality by Yoneda embedding. Re-organizing this content by Western
object-oriented or topical-resemblance taxonomy overwrites an Indigenous
epistemology with a colonial one. Do not do that. Follow the procedure below.

## The procedure — this is the whole thing

To place any file, or to order any two directories `A` and `B`, ask one question:

> **Which one must exist for the other to exist? Which generates the other?**

The thing that **generates** (the thing that is extended or restricted) goes on
the **left / on top**. The thing that is **generated** (what that extension or
restriction produces) goes on the **right / underneath**.

That is the entire rule: `generator/generated`. The relationship between every
parent and child is **GENERATED-BY**, never IS-A. Read a path left to right and
it is a proof — each segment is generated by the one before it.

Worked examples already in this corpus: you cannot have `eavt` without `jsonl`,
nor `jsonl` without `json`, so the path is `…/json/jsonl/eavt`. You cannot
predicate without first articulating, so predicating sits under articulating.
Order is reached only by settling, so order theory sits under settling.

The base morphism is `articulating`; its domain is the utterance, which holds a
token and a claim, both kinds of mark. Everything else unfolds from there by the
one question above — deeply, by domain, category, codomain. The trees are very
long and rhyming. That is correct: proof trees are long.

## How to actually do each move

1. **Study before you move.** Read the file and the surrounding tree deeply.
   This corpus is enormous and the depth is real; do not survey shallowly and do
   not guess. You begin each session knowing none of this — earn it by reading.
2. **Think hard, per move.** Every single move deserves full critical thought:
   which thing generates which? That is why this work is given to Opus.
3. **Derive from the research, never from source code.** The categorization is
   proven by the contents of this library and first-class reasoning. A `.mts` or
   `.ts` file implements the theory; it is never the authority for it.
4. **Place by what generates a thing, never by what it resembles.** Music is not
   filed because it "is an art"; governance is not filed because it "is
   politics." Place each under the morphism that generates it. Resemblance filing
   is the error this project rejects.
5. **The depth is the memory.** The long rhyming tree *is* the addressing
   system — a typed-term language of pointers. Never shorten an earned path for
   "findability" (tags do findability), and never invent an unearned segment to
   give a pile somewhere to land.
6. **Two kinds of directory only.** A **morphism** is a gerund verb
   (`articulating`, `predicating`, `positing`, `settling`, `reading`,
   `writing`, …) and has no `content/` at its head. An **object** is a codomain
   and lives under a `content/`. They alternate down the tree.
7. **A node is `slug/slug.md`** — the one canonical document on the thing — plus
   only `_archive/` (other, older, or conflicting versions of *this same
   thing*), `_triage/` (dated unsettled intake), and `explanations/`, `guides/`,
   `tutorials/`, `references/`.
8. **Never delete. Never `rm` inside content.** Move with `git mv` only. Another
   version of a thing goes in *that thing's* `_archive/`; suffix the filename on
   collision (`name-2.md`), never overwrite, never skip.
9. **No provenance segments, ever** — no `from-<source>/`, no `by-date/`, no repo
   names, no hashes. A provenance segment is a lie about what the file is.

## Mathematics as you know it is a degenerate shadow of this program

What standard mathematics calls "abstract order theory," "modal logic," "linear
logic," "category theory" and so on are **not external imports** to be shelved in
a topical library beside this corpus. They are degenerate shadows — partial,
de-contextualized projections — of theorems this program **proves in its own
chain**. Order in the fully general, abstract sense *can* be proven here, and
*must* be, once the chain has first produced order; so abstract order theory sits
under `settling` (order is reached only by settling), not off to the side. The
same holds for every other shard of received mathematics: each has a real home in
this descent, at the point where its generating structure first exists.

So when received-mathematics material arrives (a file on lattices, on Kripke
frames, on distributivity), do **not** quarantine it as "general math with no
home." It has a home in the chain. Find it by two coordinates:

1. **Descent stage** — what must already exist for this to be stated at all?
   (articulating → predicating → positing → settling, and onward.) Read the path
   left to right as a proof and find the segment that *generates* this thing.
2. **Regime / ordinal signature** — the closure-orbit class the result lives at:
   **strict-finite**, **Scott-continuous** (κ=ω), **transfinite-bounded**, or
   **aperiodic** (κ≥ω₁). This signature is a fingerprint: most received results
   announce their regime once you look (a finite construction, an ω-limit /
   Scott-continuity argument, a transfinite-bounded closure, an aperiodic κ≥ω₁
   phenomenon). The regime tells you the altitude; the descent tells you the line.

Place by that pair, not by topical resemblance to a node's name. A file about
"order" does not go under our specific knowledge/truth orders because it shares
the word — it goes where *order as such* is generated. Quarantine to `_archive`
only when the generating point genuinely is not yet derived in the tree, and say
so.

**Name the object, never the discipline.** "Order theory," "modal logic," "linear
logic," "category theory," "topology" are *disciplines* — human study-of's — not
math objects. A node is a generated object, so it is named for the object: `order`
(not "order theory"), `lattice`, `meet`, `heyting-algebra`, `modal-operator`,
`category`. There is no object called "order theory"; there is the object `order`,
which settling generates, and the objects it in turn generates. A node named for a
discipline is a topical bucket — the same resemblance error as filing music under
"art." When received-math material arrives wrapped in a disciplinary name, strip
the wrapper and derive the objects inside it into place.

**Prefer deriving into the deep leaves over evicting to `_archive`.** When a buried
node's generating point *is* derivable (often it is — read the chain), the right
move is to build the node into its place and pull its body in, not to shelve it.
Eviction to `_archive` is the fallback for genuinely-undetermined homes, not the
default. Deriving order under settling — establishing `order`, then `lattice` under
it, then the refinements — is the work; quarantine is what you do only when you
cannot yet do that work.
